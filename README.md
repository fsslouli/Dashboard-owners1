# استفسارات الملاك — البورادا فيلا

## النشر على Vercel

### الطريقة الأسهل — بدون GitHub
1. افتح [vercel.com](https://vercel.com) وسجّل دخولك (يقبل حساب Google مباشرة).
2. من لوحة التحكم: **Add New** → **Project**.
3. اختر **Deploy without Git** (أو اسحب مجلد المشروع كامل، أو اضغطه ZIP وارفعه).
4. Vercel يكتشف أنه مشروع Vite تلقائيًا. اترك كل الإعدادات كما هي واضغط **Deploy**.
5. بعد دقيقة أو دقيقتين يعطيك رابطًا جاهزًا.

### الطريقة الأفضل على المدى الطويل — عبر GitHub
1. أنشئ مستودع (repo) جديد فاضي على GitHub.
2. ارفع محتوى هذا المجلد بالكامل إليه.
3. من Vercel: **Add New** → **Project** → **Import Git Repository** → اختر المستودع.
4. Deploy. من الآن، أي تعديل ترفعه على GitHub ينشر نفسه تلقائيًا على نفس الرابط.

## التطوير محليًا (اختياري)
```bash
npm install
npm run dev
```

## ملاحظة مهمة
البيانات مطبوعة داخل `inquiries.json` بجانب `Dashboard.jsx`. لتحديثها مستقبلًا، أرسل ملف الإكسل الجديد، وسيسلَّم لك نفس هذا المجلد بالكود المحدَّث لإعادة رفعه.

## تحديث ١.١٢.٠ — رفع تلقائي لملف «تقدّم الوحدة والمراحل» (KPIs)

قبل هذا التحديث، بيانات تبويب «تقدّم التنفيذ» (المراحل والبلوكات) كانت مطبوعة داخل
الكود نفسه، وتحديثها الشهري يحتاج تعديل كود وإعادة نشر. من الآن، صار فيه زر رفع
مباشر داخل لوحة الإدارة (نفس مكان "رفع ومزامنة بيانات من إكسل") اسمه **"رفع ملف
تقدّم الوحدة"** — ترفع نفس ملف «تقدم الوحدة والمراحل» المعتاد بشكل شهري، والموقع
يتحدّث فورًا لكل الزوّار بدون أي كود أو نشر جديد.

### خطوة واحدة مطلوبة على Supabase (مرة وحدة فقط)
افتح **SQL Editor** وشغّل ملف `setup-supabase.sql` كامل من جديد — آمن تمامًا
ولا يمسّ أي بيانات موجودة (كله `create table if not exists` / `create or replace`).
هذا يضيف جدولين جديدين: `progress_matrix` (بيانات الأشهر) و`progress_matrix_backups`
(نسخ احتياطية تلقائية قبل كل رفع).

### طريقة الاستخدام
1. من لوحة الإدارة → تبويب المزامنة → زر **"رفع ملف تقدّم الوحدة"**.
2. يقرأ الملف شيت KPIs تلقائيًا بالكامل — ما يحتاج تحديد أي عمود يدويًا.
3. الشيء الوحيد المطلوب تأكيده: **سنة أول عمود** (لأن الشيت يذكر اسم الشهر بدون
   سنة) — يُخمَّن تلقائيًا من اسم الملف، وتقدر تعدّله لو غلط.
4. تظهر معاينة سريعة (أي الأشهر جديدة / تغيّرت / بدون تغيير) قبل الاعتماد.
5. ضغطة "تحديث الموقع الآن" — تُؤخذ نسخة احتياطية تلقائيًا، ثم يتحدّث الموقع فورًا.

**شهر بدون قراءة من المطور** (زي يوليو ٢٠٢٦ اللي سحبه المطوّر) يظهر تلقائيًا
"بانتظار القراءة" بدون أي تدخّل يدوي — الهدف يبقى محسوبًا من الخطة، والإنجاز
يبقى فارغًا لين توصل قراءة صحيحة.

## تحديث ١.٨.٠ — عمود «الفئة» (تصنيف نوع البند)

انضاف حقل جديد لكل استفسار اسمه `cat`، مصدره عمود **«تصنيف نوع البند»** بشيت «الاستفسارات».

### خطوة واحدة مطلوبة على Supabase
افتح **SQL Editor** وشغّل هذا السطر مرة وحدة (أو أعد تشغيل `setup-supabase.sql` كامل — كله آمن ولا يمسّ بياناتك):

```sql
alter table public.inquiries add column if not exists cat text;

insert into public.filter_categories (key, label, locked, values) values
  ('cat', 'الفئة (تصنيف نوع البند)', true,
   array['تصحيح عيب تنفيذي','تصميمي/جمالي','ترقية','استفسار فني توضيحي','تجاري','إداري/نظامي'])
on conflict (key) do nothing;
```

**لو نسيت تشغّله، الموقع ما يتعطّل ولا مزامنة الإكسل تنكسر:** الكود يفحص وجود العمود
تلقائيًا، ولو ما لقاه يتجاهل الفئة بالكتابة والمقارنة ويكمل شغله عادي، ويشتغل وحده أول
ما تضيف العمود.

### طريقة الرفع ما تغيّرت
نفس المحرك السابق: يقرأ عناوين الأعمدة بالمطابقة الذكية (تشكيل/همزات/صياغات مختلفة)،
ويقبل العنوان بأي صيغة من: «تصنيف نوع البند»، «التصنيف»، «الفئة»، «نوع البند»، «تصنيف البند».
وأي **قيمة فئة جديدة** تجي بالملف تنضاف تلقائيًا لقائمة الفلترة مثل باقي الأعمدة.
